# Agent Learning Notes

**Harness · Recursive Self-Improvement · Memory · Sandbox**

记录我学习 Agent 应用与底层工程时读到的论文、代码，以及由此产生的笔记、问题和实践。重点关注 Harness 如何组织模型、工具、上下文与执行环境，以及 RSI 如何利用反馈改进 Agent。

笔记以中文为主，保留论文原名、代码标识符与英文术语。这里会保留尚未解决的问题、没有收益的尝试，以及理解发生变化的过程。

## 关注的问题

- **Harness**：Agent Loop、工具执行、上下文管理、预算、恢复与可观测性分别在哪里实现？
- **RSI**：系统究竟修改什么，依靠什么反馈，如何判断改动带来了真实收益？
- **Memory**：哪些信息值得写入、何时检索、如何更新，以及如何验证记忆有用？
- **Sandbox**：代码在哪里执行，文件、网络、凭据和进程之间有哪些边界？

## 一条学习记录怎么产生

1. 在论文或代码索引中加入来源、一个想弄明白的问题，状态设为 `queued`。
2. 复制对应模板，记录论文版本或代码 commit，再开始写笔记。
3. 把自己的理解与来源证据放在一起；能落到实现时，关联代码笔记。
4. 有可验证的问题，再建立实验记录。记录配置、对照、结果与限制。
5. 在学习日志中留下本次进展，并把笔记关联到主题地图。

例如，一篇 Harness 论文可以关联其实现阅读笔记，再关联一个工具执行或记忆管理实验。论文、代码、实践可以相互补充。

## 状态约定

| 状态 | 含义 |
| --- | --- |
| `queued` | 已收集，尚未开始阅读 |
| `reading` | 正在读，有未完成的理解或问题 |
| `noted` | 已整理本轮笔记，结论仍可修订 |
| `experimented` | 已完成关联实验；结果需到实验记录查看 |

初始队列中的条目均为 `queued`。预建笔记是阅读起点，不代表已读完或完成复现。

## 记录时保留的证据

- 论文保留原文链接、具体版本；关键结论尽量标明章节、图表或页码。
- 代码保留仓库与 commit，重要调用链链接到该版本的文件。
- 区分作者报告、自己的理解、实际运行结果和待验证假设。
- 实验保留基线、配置、原始结果入口与失败情况；同一次测试结果不反复用于选方案。
- 公开内容只写可公开的资料和自己的笔记；密钥与私有工作资料保留在本地。
